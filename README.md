# IIPCT website rebuild

Static build of the new website for Tsi Kanonhkhwatsheríyo Indigenous Interprofessional Primary Care Team (iipct.org).

Built by [Pixel Elite Media](https://pixelelite.ca).

## Run it

Open `index.html` in a browser, or serve the folder:

```
python3 -m http.server 8000
```

The pages are plain HTML generated by the Python scripts in `tools/generator/`. Two scripts run on the site: a few
lines on the Home page that hide events once they are over and pick the next one, and, while the server copy runs at a
test address, the events reader on Home and Events & Programs (see "Live events from the server"). Every page works
without them.

## How it's put together

- One HTML file per page. Shared styles are in `assets/css/site.css`, images in `assets/img/`.
- Layout and colour are inline on the elements, because the pages were exported from the design canvas. `site.css` holds the base rules, hover states, the dropdown menus and the narrow-screen rules. Those rules use `!important` to override the inline styles.
- Breakpoints (max-width): 1399 small laptops, 1199 menu button and touch sizes, 1099 phone and tablet layout
  (photo-first hero with the horizon, a bottom bar with Call / Book / Locations, type roles), 759 tiles stack, 599
  phones (one column, two-up tiles, the phone heading scale), 374 smallest phones. Between 760 and 1099 px text and
  photo sit side by side with two and three columns of cards; between 600 and 759 px the phone's photo-first stack
  gets a wider photo. Screens under 500 px tall hide the bottom bar. Computers (1100 px and wider) keep the original
  design. The viewport tag carries `viewport-fit=cover`, and the page root and the bottom bar pad themselves by the
  phone's safe areas, so nothing sits under a notch or the home indicator.
- Desktop dropdowns are CSS only. The phone and tablet menu, the contact page questions and the staff extension lists are `<details>` elements, so they open without script.
- Fonts come from Google Fonts: Newsreader (headings), DM Sans (text), Kaushan Script (footer words).

## Where the facts live

Every phone number, fax, email, address, hour, map link and staff extension printed on the site comes from
`tools/generator/facts.py`. Each record there names its source on IIPCT's current site (iipct.org). To change one,
edit `facts.py` and regenerate. Never type a clinic fact into a page module.

- One main line, (343) 478-0196, reaches every location; callers press 1 Tyendinaga, 2 Kingston, 3 Bancroft,
  4 Deseronto, 5 Shannonville. The other numbers IIPCT publishes are fax numbers and are shown only as "Fax".
- Online booking is IIPCT's Ocean page (an outside link). This site has no forms and never collects personal or
  health information.

## Regenerate the pages

Needs Python 3 with Pillow.

```
python3 tools/generator/export_site.py .
```

Run it from the repo root. It rewrites the pages, `assets/css/site.css` and the images the pages use, and leaves
files whose content did not change untouched. Never edit a generated `.html` file or `site.css` by hand: change the
Python (`lib.py` for the shared parts, `p_*.py` for each page family, `facts.py` for the facts) and regenerate.
Real photographs go in `tools/generator/site-img/<folder>/` (listed with their source in `site-img/SOURCES.md`) and
are placed with `lib.photo()`. The page list is `PAGES` in `build.py` plus `NAMES` in `export_site.py` and the
page's row in `seo.py` (title, description, share image).

## Check the pages

```
python3 -I tools/check-site.py . --strict
```

It fails on broken links and anchors, missing images, duplicate ids, missing alt text, missing titles or
descriptions, and the search and sharing rules below (canonical, title and description lengths, share images,
structured data, sitemap, robots, redirect pages). In `--strict` it also fails on `href="#"` links, buttons that cannot
work without JavaScript, and `[bracketed]` placeholder text (allowed only on the two draft legal pages). `--online`
also tries every outside link. `--preview <folder>` checks a test copy written by the publish dry run.

## Publish the test site

```
tools/publish-preview.sh
```

It copies the pages, `assets/`, `sitemap.xml`, `robots.txt` and the old-address redirect pages from the current commit
to the `gh-pages` branch, keeps the test copy out of search engines (a `noindex` tag on every page and a robots.txt
that disallows everything), points the share tags at the test address so pasted test links show their preview card,
and pushes. The test site is https://terryjones1995.github.io/iipct/ .
`tools/publish-preview.sh --dry-run <empty-folder>` writes the files without committing; check them with
`python3 -I tools/check-site.py <empty-folder> --preview`.
That is the TEST copy: never point iipct.org at it. The live copy is `tools/publish-preview.sh --launch` (see "At
launch" below).

## Live events from the server

Until iipct.org moves, the server version of the site (the events staff publish, sign-ups, staff sign-in) runs at a
test address and this static copy stays the public front end. One constant switches the link between them:
`LIVE_SITE` in `tools/generator/lib.py` (now `"https://taylordunning.ca"`).

- **Set:** Home and Events & Programs load `assets/js/live-events.js` (a copy of `tools/generator/live-events.js`,
  written by the regenerate; never edit the copy). It asks `LIVE_SITE + "/api/public/events"` once (no cookies, at most
  4 seconds, no retry) and checks the answer strictly: JSON of the agreed shape, `site` equal to `LIVE_SITE`, every
  event link leading to a page under `LIVE_SITE + "/events-programs/"` (also once resolved, so `../` cannot climb out),
  real dates, times as the server writes them (an end may say "the next day" or "2 days later"), sizes within limits
  that sit above what the server can send (the whole answer at most 1 MB). Anything wrong, no answer, or no events:
  the page stays exactly as built (as it does with JavaScript off).
  Otherwise the server is the truth: a built card whose event the server lists (same title, ignoring case, spaces,
  dashes and quote marks, and a common day) stays, with the server's status (or none, when the server has none) or
  marked cancelled; when the server's days, times or place for it differ from the built ones, its when and where lines
  are redrawn from the server's dates (the rest of the designed text stays; the clock line, such as "Doors open at
  5:00 pm", goes when the days or times change). A built card the server does not list is hidden; an event only the
  server lists gets a card in the design's own markup (from a `<template>` in the page), in date order, linking to its
  page on the server; Home's "Up next" and "Coming up" follow the server's dates, times, places and statuses (an
  evening that runs past midnight stays listed until it ends). Text from the server is only ever inserted as text.
  `<html data-live-events>` says what happened: `shown`, `unchanged` or `error`. Every page's footer also gets a
  "Sign in" link to `LIVE_SITE + "/login"`.
- **Empty (`LIVE_SITE = ""`):** the feature is off. The regenerate writes no reader, no data attributes, no templates
  and no "Sign in" link: every page is byte-for-byte what it was before the reader existed.
- **When the domain moves to the server, this static copy is retired.** It must never go live with the reader: pointed
  at the test address it would show a test server's events, and pointed at iipct.org it would read from itself, which
  has no feed and no sign-in page. So `tools/publish-preview.sh --launch` refuses while `LIVE_SITE` is set at all, or
  while any page or file still carries the reader or the "Sign in" link. Set `LIVE_SITE = ""`, regenerate and commit first.
- Testing: `tools/live-events/` (never published) has a stand-in for the server's feed (`standin.py`), a browser
  proof that loads both pages against it in every state (`run-proof.sh` + `proof.mjs`: feed down, empty, equal to the
  built events, the server's own wording of them, an event removed, cancelled, a new or cleared status, a new event, a
  start time only, an end the next day, an evening past midnight, changed times and place, a date dropped, a second
  session, duplicate records, the longest fields the server can send, hostile answers), a proof that a visitor on a
  card's `#anchor` stays on it while cards change above it (`run-anchor.sh` + `anchor.mjs`) and a test of the
  `--launch` refusal that does not run the publish script (`test-launch-check.sh`).

## Search engines and sharing

- **One table.** Every page's title (15 to 60 characters), description (70 to 160), share-image heading and photo
  are a row in `PAGES` in `tools/generator/seo.py`. Edit the row and regenerate. Everything search engines read uses
  the real address, `https://iipct.org/` (`SITE_URL`).
- **In each page's head:** canonical address, Open Graph and Twitter tags (each on its own line), theme colour,
  home-screen icon, and structured data (JSON-LD): the organization on every page, the five locations with their
  hours on Contact (from `facts.py`, the same hours the page prints), breadcrumbs that match the visible ones, the
  news posts as articles, and upcoming dated events from the Events page's `EVENTS` list when it has one.
- **Share images:** `assets/img/og/<page>.jpg`, 1200 x 630, in the site's look, with the page's own photograph where
  it has a real one. Make them with `python3 tools/generator/og_cards.py .` (needs Google Chrome and an internet
  connection for the fonts; on the IIPCT server run it through `hof-heavy`). Re-run it when a row's heading or photo
  changes or a page is added; the regenerate prints a NOTE when a page has no share image yet.
- **Root files:** `sitemap.xml` (every public page, the date it last changed in git, its photographs) and
  `robots.txt` (allow all, points to the sitemap).
- **Old addresses keep working:** a small redirect page sits at each old iipct.org address (`contact-us/index.html`,
  `who-we-are/career-page/index.html` and so on; the list is `OLD_URLS` in `seo.py`). The same list as permanent
  (301) redirects for nginx is `tools/redirects/nginx-old-urls.conf`, with one more rule for the old calendar's
  `/event/...` pages.
- **Speed:** every image has its width and height, images below the first screen load lazily, and the hero image
  loads first.
- No tracking or verification code is on the site: Search Console and analytics need IIPCT's own Google account.

**At launch (when iipct.org points at this site):**

1. Publish the LIVE copy, never the test copy. The ordinary publish marks every page `noindex`, makes robots.txt say
   `Disallow: /`, points the canonical and share tags at the github.io address and roots the not-found page's links
   at `/iipct/`: pointed at iipct.org, that tells Google not to index the real site. The live copy is the repo's files
   unchanged (no `noindex`, the repo's robots.txt with its sitemap line, every address on `https://iipct.org/`) with
   the not-found page's links starting at `/`:
   - Kept on GitHub Pages: run `tools/publish-preview.sh --launch` (it refuses while `LIVE_SITE` names a test
     address: see "Live events from the server"). It also writes a `CNAME` file naming iipct.org,
     which gives the site that custom domain (GitHub advises adding the domain before changing DNS). Then point the
     iipct.org DNS records at GitHub Pages and, once the certificate is ready, turn on "Enforce HTTPS" under the
     repo's Settings > Pages. From then on an ordinary test publish refuses to run, so the test copy cannot replace
     the live site by mistake.
   - Served by nginx: `tools/publish-preview.sh --launch --dry-run <empty-folder>`, serve that folder, and set
     `error_page 404 /404.html;` in the server block.
   Check either with `python3 -I tools/check-site.py <folder> --launch` (for the GitHub one, a `--dry-run` of the
   same command), and confirm `https://iipct.org/robots.txt` shows `Allow: /` and the sitemap line.
2. Signed in with IIPCT's Google account, add the property for iipct.org in Google Search Console, then submit
   `https://iipct.org/sitemap.xml` under Sitemaps.
3. Confirm the old addresses redirect: https://iipct.org/contact-us/ and https://iipct.org/who-we-are/career-page/
   must land on the new pages. With nginx, include `tools/redirects/nginx-old-urls.conf` in the server block and check
   that `curl -sI https://iipct.org/contact-us/` answers `301`.
4. In Search Console, inspect `https://iipct.org/` and request indexing of the home page.

If the real address is ever different (`www.iipct.org`, say), change `SITE_URL` in `seo.py`, `REAL` in
`tools/check-site.py` and `REAL_URL` in `tools/publish-preview.sh`, then regenerate.

## Before this goes live

**Legal pages.** Privacy Policy and Accessibility are drafts. Highlighted `[bracketed]` items need IIPCT's details
(privacy officer, analytics, safeguards, accessibility contact, clinic accessibility), and the wording needs their sign-off.
That includes the plain-text promises IIPCT has not made anywhere yet: the WCAG 2.0 Level AA goal, service animals,
support persons and assistive devices, notices of service disruptions, and "We don't sell personal information".
The "Services we use" list names BambooHR because the Careers page is getting its job links; drop that row if it does not.

**Facts to confirm with IIPCT.** Tyendinaga opens at 7:30 am on Fridays (as the current contact page says; every other
day opens at 8:30). The Deseronto waitlist flyer says "press 3" but the contact page says Deseronto is option 4 (the
site uses 4). Deseronto's postal code is not printed anywhere by IIPCT, so it is left off. The staff extension lists
are copied from the current contact page and will go out of date as staff change.

**Events and news.** Events & Programs, the upcoming events on Home and the News page are built from IIPCT's public
Facebook posts (April to November 2026) and the old site; every item traces to one of those posts or pages. An event
drops off the Home page by itself once it is over. The built lists are part of the pages; while `LIVE_SITE` is set the
two lists follow the events staff publish on the server (see "Live events from the server"), and with it empty new
events are added in `tools/generator/p_events.py` and the pages regenerated. Posts from before April 2026 could not be read without signing in to Facebook; a page export from IIPCT
would fill in the rest of the year.

**Pictures.** The photographs of people and places are IIPCT's own, from the old site and their Facebook page (each one
is listed with its source in `tools/generator/site-img/SOURCES.md`). Ask IIPCT to confirm they are happy with the staff
photographs being used. Ten pictures are still stand-ins from the design mock-ups, all scenery or still life with no
people in them: the five banners on the Contact page's location cards (`con-*.jpg`), the three pictures on the
Services page (`svc-*.jpg`), `home-smudge.jpg` on Home and `evt-featured.jpg` on News. Photographs of the real
locations would be better.

**Logo.** `assets/img/logo-emblem.png` is a cleaned-up copy of a 216 px file. Get the original vector from IIPCT.

**404 page.** `404.html` uses relative links in the repo. The publish step rewrites them to start at the site root
(`/iipct/...` on the test site, `/...` with `--launch`), so the page keeps its styles and working links at a missing
address of any depth. The old iipct.org addresses (`/contact-us/`, `/who-we-are/career-page/` and the rest) do not
reach it at all: each has a redirect page to its new page (see "Old addresses keep working" above).
